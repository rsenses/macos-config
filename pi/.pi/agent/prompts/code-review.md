Validate, correct, and review: $ARGUMENTS

Load `ops` and read `~/.agents/skills/ops/references/brief.md` and `~/.agents/skills/ops/references/review-findings.md`. This invocation explicitly requests `code-reviewer`, full project validation, and bounded worker corrections before/after review; it does not change ordinary development policy. Preserve safety/approval gates. Do not commit, push, open PRs, install hooks, or create plans/review artifacts just for this workflow.

1. **Scope.** Resolve the original request, clarifications, decisions, and current contract if any. Use the supplied scope, otherwise current local changes including relevant untracked files. Ask about material ambiguity; never substitute another target. Preserve unrelated work.
2. **Validate and correct.** Discover existing commands in project instructions, scripts, and CI. The principal runs the project's configured fixers/formatting, lint, static analysis/type checks, entire test suite (including architecture tests), and required build before the reviewer and again after corrections, including review fixes. Targeted checks may diagnose failures but never replace full validation. Use workers with ops briefs for confirmed in-scope fixes; distinguish pre-existing failures and environment blockers. Do not weaken tests/rules or change requirements to obtain green results. Inspect worker changes and rerun full validation after corrections. Validate a stable tree, including final fixer writes; reuse success only while inputs remain unchanged. Unclear commands or unresolved validation failures block review.
3. **Demonstrate.** If the suite does not establish the changed behavior, perform the smallest relevant reproduction/exercise with available tools. Prefer permanent regression coverage when warranted, not mandatory scratch tests. Report unavailable checks as limitations. Any changes require full validation before review.
4. **Review.** Invoke one read-only `code-reviewer` through `subagent`, using ops' brief and existing review criteria. Supply intent/clarifications, decisions, contract, updated diff/new files, readable project/skill references, validation/behavioral evidence, and limitations. Do not add routine reviewers or a judge. Reviewer failure blocks completion; do not substitute another agent.
5. **Resolve.** Assess findings under the shared findings contract; verify hypotheses with minimum checks, correct supported in-scope defects through workers, and leave optional improvements unimplemented. Inspect corrections and rerun full validation, not just affected tests. Allow at most one focused correction review when substantive fixes warrant it; any subsequent corrections also require full validation. Return persistent defects or nonconvergence to the user instead of starting further rounds.
6. **Report.** Summarize scope/outcome, corrections, relevant dismissed/unresolved findings, exact commands/results, behavioral evidence, and checks not run under ops' reporting contract. No findings does not establish production readiness.
